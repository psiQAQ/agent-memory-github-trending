# 术语与证据等级

| 术语 | 在本项目中的含义 | 不代表什么 |
| --- | --- | --- |
| 上游说明 / upstream_statement | 来源作者在 README、Release 等处的声明 | 本仓库已运行或验证效果 |
| 代码静态核查 / code_inspected | 阅读了指定版本的实现或差异 | 测试通过、成本下降、性能提升 |
| 独立复现 / independently_reproduced | 另行获批后实际运行、记录环境与结果 | 仅看代码或转述上游测试 |
| 已合并未发布 / merged_unreleased | 变更进入主开发分支，尚未确认进入对应 Release | 已安装版本一定有此功能 |
| 已发布 / released | 有正式版本及对应证据 | 该版本适合所有用户或没有回归 |
| 固定版本 / pinned HEAD | 在一个确定 commit 上读取和比对 | 随时变化的 main 分支内容 |
| 快照 / snapshot | 一轮实际采集的不可变 JSON | 连续每日观测或完整历史 |
| 成功游标 / watermark（水位） | 上次确认成功且完整的采集位置 | 失败时可以跳过的数据 |
| 历史补采（回灌） | 补读此前未收集的发布或观测 | 可以补造当时的精确 Star 数 |
| Release 增量完整 | 已读到上次成功记录，或确认列表结束 | 历史所有 Release 都已下载 |
| 回执 / receipt | Data commit 回读后单独提交的状态确认 | 数据提交前预先假定成功 |
| 事件回填 / structured-event backfill | 将已有证据补成结构化事件记录的待办 | 新发生的技术新闻 |
| — / null / 未核实 | 缺少满足口径的证据 | 零、没有变化、没有许可证 |

“基线就绪”要求目标时刻前后 6 小时内存在真实观测，并有本次成功数据。两次记录相隔约 18 小时，只能报告这段实际区间的净变化，不能称为 24 小时或 7 日增长。
