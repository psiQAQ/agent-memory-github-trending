# 筛选与统计方法

方法版本：1.0，默认方案于 2026-09-16 获批准。阈值属于本项目工作规则，不是 GitHub 官方标准或经验证的预测模型。

## 收录与分类

研究对象为具有可检查的记忆写入、组织、检索、更新、压缩、遗忘、经验复用机制，或相应评测资产的 Agent 项目。工程、研究代码、评测和背景参照分开，不把整个框架的总 Star 当作其 memory 子模块的热度。

保留通用记忆层、有状态 Agent、Coding Agent 记忆、图/时间记忆、压缩维护、经验/程序性记忆、评测标签。研究时可进一步标注文本/结构化、参数或潜在状态载体，以及事实、经验、工作记忆功能和形成、演化、检索操作；分类线索参考 [Agent Memory Survey](https://github.com/Shichun-Liu/Agent-Memory-Paper-List)。

排除纯缓存/内存分配、普通聊天 UI、没有记忆机制的 RAG、SEO 空壳、镜像和无独立贡献的 fork。静态提示词模板可作背景，不直接等同于持久记忆实现。首次公开时间未知就为 null；仓库创建时间不代表公开发布。迁移后仓库 ID 不同则独立记录，不拼接 Star 历史。

候选不设全局最低 Star。每轮同时检查既有对象和无 Star 门槛的新项目通道，具体关键词和查询模板见 `config/queries.json`。综述、Topics、GitHub Trending 和 Awesome List 仅为发现线索。正式收录须阅读一手说明、识别实现或评测资产、记录证据和未验证项。未审查候选不是推荐。

## 查询覆盖

记录实际查询、时间、排序、页码、返回数、incomplete_results 和分页完整性。连接器没有暴露的字段为 null；只取第一页不能声称全量。查询结果不是全生态普查，返回条数不能直接当作整个技术方向的新项目数量。

首次登记目标 20 个，含候选的总观察池不超过 50 个。每轮最多审查 10 个新候选和 5 个实质变化，观察池 72 小时轮询。正式项目通常每 12 小时检查；超额或失败项记录队列和实际覆盖，不假装完成。

## 三个独立视图

新发现展示首次发现、创建时间、机制和收录理由；关注度展示同窗口 Star 净变化、原始基数和增长率；实质进展解释记忆方法、实现、宿主接入、版本、许可证或相关公开安全变化。待审 PR、已合并未发布和正式发布分开。

工程与 benchmark 不混成总榜；成熟参照与新实现分开。单纯 HEAD/计数变化不代表技术突破。首轮读到的历史发布只是基线，不是本轮发生的新闻。

## 数值口径

所有观测记录来源 URL 和实际观测时间。首轮时间标为 batch_completed_at，表示工具读取批次结束时间，元数据与 HEAD 并非原子采集；后续优先逐来源记录完成时间。API 获取失败时新观测字段为 null 且带原因，显示层和游标保留上次成功值并标为 stale。不可从缓存搜索摘要补造精确计数。

设成功观测为 `(t0,S0)` 与 `(t1,S1)`：净变化是 `S1-S0`，允许负值；日均净变化为差值除以实际经过天数；相对增长是差值除以 `S0`，仅在 `S0>0` 时定义。Star 总数下降不是抓取错误的充分证据。

7/30 日窗口选择离目标时刻最近且偏差不超过 6 小时的真实观测，公开实际天数与基线时刻。没有对应基线时为 null，显示“—”；不将半日变化外推一周，不用总 Star 代替增长。脚本的 growth() 返回原始基数、净变化、日均速度和相对变化；初期不发布加速度排行。

关注度候选提示：24 小时净增至少 100；或 7 日净增至少 100 且增长率至少 20%。这些不是质量分、技术突破或刷 Star 判断。只有关注度变化默认留在观测表/周报，不独立推送技术通知。

Release 分页不完整不得推进成功游标。GitHub open_issues_count 包含 PR，不能直接标成 Issue 数；贡献者总数不等于活跃贡献者数，pushed_at 不等于质量。首版没有独立 PR/贡献者总量榜。

## 证据和报告

关键结论记录 claim、source_url、source_version_or_sha、event_at（未知为 null）、observed_at、evidence_level。README 说明属于 upstream_statement；检查对应代码后才可使用 code_inspected。初期禁止执行上游代码，不出现 independently_reproduced。

记忆卡片说明保存形式、写入/检索/维护过程、接入、依赖、许可证来源、评测证据与未知项。自托管不等于无模型网络调用；托管平台的专有实现和成绩不能归给开源库。跨项目对比须核对数据集、模型、配置和评价协议，不兼容的性能数字不得横排。

周报采用同一组已跟踪仓库比较，再说明新收录导致的样本变化。至少多个独立项目有证据才讨论共同方向，否则标“单项目观察”。监测开始所在周是部分周，不假装已有整周覆盖。事件由稳定 ID 去重，纠错明确 supersedes，不修改历史记录掩盖错误。
